# 输入与样式说明书

两个指标：`quasimodo_zones.pine`（QM 供需区）、`impulse_wave_12345.pine`（推动浪 1-2-3-4-5）。

---

## 先说一件会反复踩到的事：输入页 vs 样式页

TradingView 的**「样式」标签页只接受 `plot` 家族的输出** —— `plot` / `plotshape` /
`plotchar` / `fill` / `bgcolor` / `hline`。这几种东西才会出现在样式页里，带着颜色选择器、
不透明度滑块、厚度、线条样式那一整套控件。

**`line` / `box` / `label` / `table` 这类绘图对象永远进不了样式页。** 这是 TradingView
的设计，不是脚本的取舍。而 QM 的区域框、推动浪的浪线，只能是绘图对象——因为它们连接
的是**任意两根 bar**，`plot` 做不到（`plot` 每根 bar 只能给一个值）。

所以两个脚本都是**双层**的：

| | 画什么 | 在哪调 |
|---|---|---|
| 绘图对象层 | 区域框、QM 虚线、浪线、推演斜线、点位标签 | **输入页 · ④ 样式** 组 |
| plot 层 | 最近的那对供需区、推演目标价、事件标记、背景 | **样式页**（你截图里那套 UI） |

两层是**重叠**的。只想要一层：在样式页把 plot 层全部取消勾选，或者反过来，把输入页
④ 组里的标签/骨架开关关掉。

# 一、`quasimodo_zones.pine`

## ① 摆动点

### `Pivot 左侧根数` — 默认 5

`ta.pivothigh(high, left, right)` 里的 `left`。一个 bar 要成为摆动高点，它的最高价必须
**严格高于左边 5 根**的最高价。

- **调大**：结构更少更粗，只认大波段。日线做波段建议 8–15。
- **调小**：结构更碎，噪声多。`left=2` 在 15 分钟图上会遍地是形态。
- 这个数字**不是时间**，是根数。日线 5 = 一周，1h 图 5 = 5 小时。换周期要重调。

### `Pivot 右侧根数` — 默认 5

`right`。同样是根数，但它额外决定了**确认延迟**：枢轴要等右边 5 根走完才能确认，
所以形态最早只能在真实 LL 之后 5 根被报出来。

这不是缺陷，是「不偷看未来」的代价。**想让信号更早来就调小，但结构会变碎；两者不可兼得。**
一般让它等于 `left`。

## ② 区域

### `ATR 周期` — 默认 14

只用来量「一个正常的波动幅度是多大」，给区域厚度定基准。14 是 Wilder 原始值，
没有特别理由要改。

### `区域最小厚度 = ATR ×` — 默认 0.5

区域厚度取 `max(枢轴那根的影线长度, ATR × 这个倍数)`。

**为什么要有下限**：如果 H 那根是根光头阳线（没有上影线），影线长度是 0，区域会退化成
一条零厚度的线，价格永远「碰不进去」。这个倍数就是兜底。

- **0.5** ≈ 半个日波动。BTC 日线上大约 1.5–2%。
- **调大到 1.0–1.5**：区域变厚，更容易被碰到，信号更多但更松。
- **调到 0**：完全依赖影线长度，遇到光头K线就出问题。不建议。

### `区域构造` — 默认「QML 向外扩」

这是**你规格书里唯一一处真正含糊的地方**，两种读法结果不同：

| 选项 | 看跌区 | 区域在 QM Level 的 |
|---|---|---|
| **QML 向外扩**（你写的） | `[QML, QML + 厚度]` | **上方** |
| 枢轴K线影线（常见画法） | `[H那根实体上沿, H那根最高价]` | **下方** |

差别不是美观问题——它决定了「价格进区」发生在**突破 QML 之前还是之后**。
第一种：价格必须先涨到 QML 才算进区。第二种：价格还没到 QML 就已经进区了。

### `保留最近几个形态` — 默认 10

FIFO 上限，超出就删最旧的那个（连同它的框、线、5 个标签 = 7 个对象）。

**为什么要有上限**：TradingView 每个指标最多 500 条线 / 500 个 box / 500 个 label。
撞上限之后 TradingView 会**静默丢弃**最老的对象，看起来就像「有的线不见了」。
10 个形态 = 70 个对象，很安全。调到 60 = 420 个，接近天花板了。

## ③ 显示 / 警报

| 输入 | 默认 | 说明 |
|---|---|---|
| 看跌 · 供给区 | `#ef5350` 红 | 框、虚线、H/L/HH/LL 标签的颜色 |
| 看涨 · 需求区 | `#26a69a` 绿 | 同上，镜像 |
| 已失效 | `#787b86` 灰 | 形态死掉后，**五个标签 + 框 + 虚线一起变灰** |
| 区域填充透明度 | 88 | 0 = 实心，100 = 全透明。88 大约是一层薄色 |
| 标注 H/L/HH/LL | 开 | 关掉能省 4 个对象/形态，密集时有用 |
| 标注 QM | 开 | 触发之后这个标签会变成 `QM ✓` |
| 隐藏已失效形态 | 关 | 打开 = 死掉就**删除**（不是变灰）。想只看活跃区就打开 |

## 四个状态怎么读

```
形成  ──► 回踩进区 ──► 触发
  │                      （框边框加粗 + 标签打勾 QM ✓）
  └──► 失效（全部变灰，框停止向右延伸）
```

- **形成**：H→L→HH→LL 确认。注意是在真实 LL 之后 `right` 根。
- **回踩进区**：看跌时 `high ≥ 区域下沿`。只触发一次。
- **触发**：进过区之后，出现一根**收盘回到区外**的K线。默认模式下区域下沿就是
  QM Level，所以等价于「收盘价低于 QM Level」。**进区和触发允许在同一根**——
  上影线插进去、收盘掉回来，那正是经典的拒绝形态。
- **失效**：收盘价穿出区域**外沿**（看跌 = 上沿）。

# 二、`impulse_wave_12345.pine`

## ① ZigZag（ATR 反转阈值）

### `ATR 周期` — 默认 14

这里的 ATR 不是装饰，它**定义了整个枢轴序列**。阈值 = `ATR(14) × 倍数`。

### `级别 A / B / C 阈值 = ATR ×` — 默认 2 / 4 / 8

**这是全脚本最重要的三个数字。** 一条腿必须让收盘价从极值反向走出
`ATR × 倍数` 才算结束，否则一直延伸。

为什么用 ATR 而不是 pivot 的根数：`left=5` 在暴涨和横盘里量到的东西完全不是一回事；
你要的三个级别是**幅度**，不是根数。用根数做级别，三条 ZigZag 在高波动段会塌成同一条。

实测（本仓库 SOL 日线 1713 根）：

| 级别 | 阈值 | 确认的枢轴数 | 有效数浪 |
|---|---|---|---|
| A | ATR×2 | 120 | 0 |
| B | ATR×4 | 46 | 3 |
| C | ATR×8 | 12 | 0 |

**A 是 0 不是 bug**：它那两组命中的浪里都有两个枢轴落在同一根K线上（零长度线段），
被 `rBi` 规则筛掉了。**C 是 0 也不是 bug**：它唯一一组跨 752 根，被跨度上限筛掉了。

调参时先打开 ④ 组的 `画出 ZigZag 骨架`，肉眼看三条折线是不是三个层次。
**塌成同一条就把倍数拉开**，比如 ×1.5 / ×4 / ×10。

### `阈值按周期自动缩放` — 默认 **开**

**打开时下面三个手动值不生效**，脚本按图表周期自己选：

| 图表周期 | A / B / C |
|---|---|
| 月线 | 0.25 / 0.5 / 0.75 |
| 周线 | 0.5 / 1.0 / 1.5 |
| 日线 · 4小时 | 2 / 4 / 8 |
| 4小时以下 | 3 / 6 / 12 |

状态表第二列显示的是**实际生效**的倍数，表头会写 `阈值(自动)` 还是 `阈值(手动)`。
想手动调就把这个开关关掉。下面这一节讲的是为什么需要它。

### ⚠ 为什么阈值不能跨周期通用

阈值是 ATR 倍数，**幅度上跨周期自适应，但枢轴数量不会** —— 枢轴数取决于图上有
多少根K线。同样的倍数，日线有 1700 根可用，周线只有 250 根。

实测（本仓库数据重采样，截至 2026-09-09）：

| ETH | 总根数 | ATR×2 | ATR×4 | ATR×8 |
|---|---|---|---|---|
| **日线** | 1713 | **114** 枢轴 | 42 | 15 |
| **周线** | 246 | **14** 枢轴 | 7 | **3** |

**3 个枢轴连一个 6 点窗口都凑不出来**，所以周线上级别 C 永远是空的。
这不是 bug，是默认值只按日线校准。

周线上把三个倍数缩到**日线的 1/4 左右**，枢轴密度就回来了：

| ETH 周线 | ATR×0.5 | ATR×1.0 | ATR×1.5 | ATR×2.0 |
|---|---|---|---|---|
| 枢轴数 | 112 | 48 | 28 | 14 |
| 命中 | 1 | 1 | 0 | 0 |

**推荐起点**

| 周期 | A / B / C |
|---|---|
| 1周 | 0.5 / 1.0 / 1.5 |
| 1天 | 2 / 4 / 8（默认） |
| 4小时 | 2 / 4 / 8 |
| 1小时及以下 | 3 / 6 / 12 |

上面那个自动开关就是干这件事的。手动模式下，状态表的 `枢轴·命中` 列是给这件事看的：
**枢轴数低于 12 会直接报「⚠ 枢轴仅 N 个，阈值偏大 · 试试调到 1/4」**。

### `启用级别 A / B / C` — 默认 开 / 开 / **关**

C 默认关，因为日线上 ATR×8 的浪以年计，基本都会被跨度上限筛掉。
低周期（15m / 1h）上 C 才有意义。

## ② 校验规则

三条硬规则写死在代码里，不可调（那是艾略特的定义，调了就不是推动浪了）：

```
浪2 不跌破浪起点 P0
浪3 不是 1、3、5 中最短的
浪4 不进入浪1 的价格区间
```

顺带一提：这三条**已经蕴含「P3 越过 P1」**（因为 P4 越过 P1 且 P3 越过 P4），
所以不需要单列第四条。

### `浪4 允许重叠浪1 的比例` — 默认 0（严格）

「浪4 不进浪1 价格区间」是艾略特最硬的一条。但**对角线形态（leading / ending
diagonal）在艾略特里本来就允许重叠**，所以给一个容差，单位是浪1 长度的比例。

实测 BTC 日线（2026-09-09 收盘）三个级别的浪4 侵入量：

| 级别 | 浪1 长度 | 浪4 侵入 | 占浪1 |
|---|---|---|---|
| A | 23,749 | 7,844 | **33.0%** |
| B | 45,608 | 2,229 | **4.9%** |
| C | 35,543 | 8,372 | **23.6%** |

设到 `0.06`，级别 B 那一组 1-5 成立并画出推演；A 和 C 仍然出局。

**调这个值是在放宽定义，不是在改进检测。** 放得越宽，命中越多，含义越少。

### `浪5 必须超越浪3 端点` — 默认 开

这是三条之外我加的。关掉 = 允许**衰竭浪**（truncated fifth）。
衰竭浪在艾略特里合法但少见；默认打开能少掉很多噪声数浪。

### `浪3 ≥ N×浪1 时加粗标 ★` / `加分比例 N` — 默认 开 / 1.618

**纯装饰，不影响是否命中。** 斐波那契比例是加分项不是硬条件——把 1.618 当门槛
会筛掉大量真实的推动浪。达标时浪3 那一段线加粗、标签加 ★。

### `每个级别保留最近几组` — 默认 1

三个级别 × 2 组 = 30 条浪线 + 3 条推演线抢同一片像素。默认 1 组，想看历史再往上加。

### `一组浪最大跨度（根，0 = 不限）` — 默认 300

**这条是为了让线跟着价格走。**

一组浪的连线是两个枢轴之间的**直线段**。枢轴隔了几百根的时候，两端都在屏幕外，
中间那条直线就横穿图表，落在和当地K线毫无关系的价位上——看起来就像「线没跟着价格变化」。

实测：SOL 日线 ATR×8 唯一一组浪跨 **752 根**（2022-12 的 7.78 到 2025-01 的 295.60）。
默认 300 把它筛掉。

**副作用**：日线上级别 C 经常是 0 组。那不是坏了，是日线上 ATR×8 的浪本来就以年计。
想看就把这个数调到 0（不限）或 800。

## ③ 推演

**推演画的是 1-5 之后的 ABC 调整目标，不是第 6 浪。** 这是几何外推，不是预测。

### `推演价位：回撤 1-5 全长的` — 默认 0.5

```
看涨：目标 = P5 − (P5 − P0) × 这个比例
看跌：目标 = P5 + (P0 − P5) × 这个比例
```

常用值：0.382（浅调整）、0.5、0.618（深调整）。

### `推演耗时：1-5 跨度的` — 默认 0.5

决定推演斜线的**终点在第几根**：`P5 所在 bar + (P5 − P0 跨的根数) × 这个比例`。
只影响斜线的斜率和终点位置，不影响目标价。

### `只给每个级别最新的一组画` — 默认 开

推演的终点是 P5 之后若干根。**如果那一组浪早就走完了，终点就落在已经发生过的历史里**——
那不是预测，是一条画在旧K线上的斜线，而且和浪线长得像，认不出来。

配套还有一条自动清理（不可关，写死的）：**价格走过推演终点之后，斜线、射线、标签
全部删除，浪线保留。** 实测 SOL 日线上，三个级别最新的推演分别已经过期
1010 / 514 / 222 根——不清理的话就是三条对过去做的预测挂在图中央。

### `画待定推演（浪5 还在走的时候）` — 默认 开

**这是「先假设一条，成立后再换成正式的」那个功能。**

正式推演要等 6 个枢轴全部确认。在那之前，只要**前 5 个点**已经构成合规的浪1-4 前缀、
而且当前那条未确认的腿正往浪5 的方向走，就先按斐波那契假设一条：

```
假设浪5 终点 = P4 ± 浪1 × fib5，再过三道夹紧：
  ① 浪3 比浪1 短时，浪5 不能超过浪3（否则「浪3 不是最短」被自己破坏）
  ② 若「浪5 超越浪3」开着，强制超过 P3
  ③ 实时极值已经走过假设终点的话，用实时极值 —— 浪5 在延伸
再从那个假设的 P5 推出调整目标（和正式推演同一套公式）
```

画法**刻意和正式推演区分**：点线、另一种颜色（默认 `#90a4ae` 灰蓝）、标签写「待定」。

**它每根都会变。** 实时极值一动，假设的 P5 就动，目标跟着动。浪5 一确认，
待定线消失，正式推演接上；已经有正式推演在图上时不画待定（免得两条线打架）。

**这是假设，不是信号。** 唯一的用处是提前知道「如果这一浪按教科书走，目标大概在哪」。

### `待定：预期浪5 = 浪1 ×` — 默认 1.0

1.0 = 等长浪，艾略特最常见的指引。0.618 = 偏保守，1.618 = 延长浪。

### `在目标价上画一条水平射线` — 默认 开

点状、向右无限延伸。**斜线只说「往那边走」，射线才让目标价可读**——你能直接看出
当前价离目标还有多远。

# 三、样式页里有什么

## QM（13 项）

| 条目 | 类型 | 说明 |
|---|---|---|
| 最近供给区 上沿 / 下沿 | plot | 只画**离现价最近**的那一对，不是全部（全部已经由 box 画了） |
| 最近供给区 填充 | fill | 两条线之间 |
| 最近需求区 上沿 / 下沿 / 填充 | plot ×2 + fill | 镜像 |
| 事件 · 看跌 / 看涨 QM 形成 | plotshape | 三角，K线上/下方 |
| 事件 · 回踩进区 / 触发 / 失效 | plotshape | 圆 / 菱形 / 叉 |
| 背景 · 现价在供给区内 / 需求区内 | bgcolor | 整根背景上色 |

「最近的那一对」是个和 box 层不同的视角：box 画的是全部历史区域，plot 画的是
**现在真正挡在你前面的那个价位**。

## 状态表第三列：为什么没有线

右下角状态表加了「当前状态」列，直接写出卡在哪一条，不用再猜：

| 显示 | 含义 |
|---|---|
| `待定 ↑ 浪5 进行中` | 正在画待定线 |
| `正式推演进行中` | 已有确认的推演，不画待定 |
| `浪2 跌破起点` / `浪4 重叠浪1 4.9%` | 那一条规则没过（重叠会给出具体百分比） |
| `有两点同根K线` / `跨度 527 超限` / `枢轴不交替` | 结构性出局 |
| `不在浪5 方向` | 前缀合规，但当前腿方向不对（可能在走调整） |
| `枢轴不足 3/5` | 刚加载，数据不够 |
| `⚠ 枢轴仅 7 个，阈值偏大` | **换周期后没调阈值**，见上面那张表 |

实测（本仓库数据，截至 2026-09-09），40 组「品种 × 周期 × 阈值」里有 4 组能画出待定线：

| 品种 | 周期 | ATR× | 假设浪5 | 待定目标 | 现价 |
|---|---|---|---|---|---|
| ETHUSDT | 1d | 1.5 | 2,826 | 2,169 | 2,467 |
| ETHUSDT | 4h | 3.0 | 2,566 | 2,209 | 2,461 |

# 六、必须知道的四条

1. **重绘。** QM 不重绘（`ta.pivot*` 是局部的，只看左右各 N 根）。推动浪的
   **最新一浪会重绘**，而且 ZigZag 路径依赖——往左拖加载更多历史后整串枢轴可能挪位。
   这不是实现缺陷，是 ATR-ZigZag 没有「局部」定义：第 k 个枢轴取决于第 1 个。

2. **确认延迟。** QM 的形态在真实 LL 之后 `right` 根才报出来。区域框画在 LL 那根，
   但**监控是从确认那根开始的**——框覆盖的前 `right` 根从未被判定过。

3. **对象上限。** 每指标 500 线 / 500 box / 500 label。撞上限 TradingView 会**静默丢弃**
   最老的对象，看起来就像「有的线不见了」。保留数调大之前先算一下。

4. **没有在 TradingView 上编译运行过。** 我没有 Pine 编译器。两份代码做过静态审查
   （括号配平、声明顺序、函数先定义后调用、`plot` 家族在全局作用域、
   无 `int/int` 整数除法、循环边界不出现 `0 to -1`、**续行缩进不是 4 的倍数**），
   核心算法另外用 Python 在真实 SOL 日线上逐行对过。报错把行号发我。
