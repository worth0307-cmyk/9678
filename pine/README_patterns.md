# 形态识别指标（Pine v6）

两个 overlay 指标，共用同一套骨架：

| 文件 | 形态 |
|---|---|
| `quasimodo_zones.pine` | Quasimodo（QM）供需区：H → L → HH → LL 及其镜像 |
| `impulse_wave_12345.pine` | 推动浪 1-2-3-4-5，三级别 ZigZag 并行 |

骨架是 **①输入 → ②枢轴序列 → ③形态对象 → ④检测 → ⑤每根维护 → ⑥警报**，
换形态时只改 ④。

---

## 共同的设计

**不使用未来数据。** `ta.pivothigh/low` 有 `right` 根确认延迟，所有绘图都回溯锚定到
`bar_index - right`；ATR-ZigZag 的枢轴只在收盘价反向走出阈值时才确认，极值点本身在
过去。两者都是"报得晚"，不是"看得早"。

**对象上限。** TradingView 每个指标最多 500 条线 / 500 个 box / 500 个 label。两个脚本
都用 FIFO 数组管理生命周期，超出 `保留最近 N 个` 就删最旧的。

**枢轴强制高低交替。** `ta.pivothigh` 可以连着出两个高点而中间没有低点（H, H, L）。
不归一化的话"倒数第 4 个点"根本不保证是高点，形态判定会错位。做法是：相邻同类型
只保留更极端的那个。

## QM：我对你规格书做的判断

你的规则里有三处需要定，我的选择都做成了输入，翻起来是一行的事。

**1  区域画在 QM Level 的哪一侧。** 你写的是"下沿为 QM Level、厚度向外扩"，
那么看跌区 = `[QML, QML + max(H那根上影线长, ATR×0.5)]`，**整体在 QML 之上**。
但供需区更常见的画法是把 H 那根的影线本身当区域，即 `[实体上沿, 最高价]`，
**整体在 QML 之下**。两者的差别不是美观问题——它决定了"价格进区"发生在
突破 QML 之前还是之后。默认按你写的来，`区域构造` 可切到另一种。

**2  "触发"的参照价。** 你写"进区后出现收盘价低于 QM Level 的K线"。在默认模式下
区域下沿**就是** QM Level，所以我把判定统一写成"收盘回到区域外沿之外"——默认模式下
与你的原话逐字等价，切到影线模式时会自动对齐到区域边界，不会变成一进区就触发。
另外：进区和触发允许发生在**同一根**K线上（上影线插进去、收盘掉回来），那正是
经典的拒绝形态，不该被排除。

**3  LL < L 用影线还是收盘。** 用枢轴价（影线）。要求收盘跌破会少掉相当一部分
形态，但会更"干净"；想改的话把 `d.price < b.price` 换成对收盘的比较即可。

QM Level 那条虚线从**左肩 H** 画起（看得见这条位的来历），区域按你说的从 **LL** 画起。

## 推动浪：我对你规格书做的判断

**1  为什么不用 pivot 做 ZigZag。** 你写"pivot 或 ATR×倍数"。选了后者：pivot 的
`left/right` 是**根数**，同一个 `left=5` 在暴涨和横盘里量到的东西完全不是一回事；
而你要的三个级别是 ATR×2/×4/×8，那是**幅度**。用根数做级别会让三条 ZigZag 在
高波动段全部塌成同一条。

**2  加了第四条硬规则，可关。** 你列了三条（浪2不破起点、浪3不最短、浪4不进浪1区间）。
我加了"浪5 超越浪3 端点"并默认打开——关掉就允许衰竭浪。衰竭浪在艾略特里合法，
但打开能少掉很多噪声数浪。注意你那三条已经蕴含 `P3 越过 P1`（因为 P4 越过 P1 且
P3 越过 P4），所以不需要单列。

**3  "下一段"指的是调整，不是第 6 浪。** 1-5 走完之后接的是 ABC。虚线画的是
`P5 回撤 (1-5 全长) × 比例`，默认 0.5，横轴用 1-5 跨度的 0.5 倍估耗时。
这是一个**几何外推**，不是预测。

推演有一个陷阱值得单说：它的终点是 `P5 之后若干根`。如果那一组浪早就走完了，
**终点就落在已经发生过的历史里**——那不是预测，是一条画在旧K线上的斜线，
而且和浪线同色同形，在图上根本认不出来。所以：推演有自己的颜色/线宽/样式，
默认只给每个级别**最新**的一组画，并且在目标价上另外画一条向右延伸的点状射线
（斜线只说"往那边走"，射线才让目标价可读）。

## 重绘

| | 会不会变 |
|---|---|
| QM 已确认的枢轴、区域边界 | 不变 |
| QM 的失效/触发状态 | 只前进不后退，判定用收盘价 |
| ZigZag 已确认的枢轴 | 不变 |
| **最新那一浪** | **会变**：当根K线走完前反复出现/消失；下一个枢轴确认后，整组数浪可能被一组不同的数浪取代 |
| **往左拖加载更多历史之后** | **会变**：ZigZag 是路径依赖的，它从图表最早那根开始滚。起点换了，整串枢轴可能整体挪位 |

在实时图上，任何"最新信号"都要等收盘。这不是实现缺陷，是数浪这件事本身的性质。

最后一行也不是 bug：ATR-ZigZag 没有"局部"定义，第 k 个枢轴取决于第 1 个枢轴。
方向播种已经改成"双向跟踪、谁先反转谁定方向"（旧版硬性假设第一条腿向上，
那会让最早几个枢轴系统性偏一边），漂移被压小了，但压不到零。
QM 那份没有这个问题——`ta.pivot*` 是局部的。

## 已知局限

1. **同一根K线上同时出现枢轴高点和低点**（极端内包线）时，两个枢轴会共用一个
   `bar_index`。罕见，不影响判定，但连线会有一段零长度。
2. **ZigZag 的初始方向是硬播种的**（首根假设上升腿）。前一两个枢轴可能偏，
   之后自动收敛。
3. **重叠数浪不去重**：相邻两次枢轴确认可能各自成立一组 1-5，窗口错开一位。
   两组都合法，靠 `每个级别保留最近几组`（默认 2）限制杂乱度。
4. **推演虚线最远只画到当前 bar 右侧 450 根**（TradingView 上限 500），
   跨度极大的级别会被截断，斜率随之改变。
5. **没有在 TradingView 上编译运行过。** 我没有 Pine 编译器；这两份代码做过静态
   审查（括号配平、声明顺序、函数定义先于调用、无 `int/int` 整数除法、
   不对函数调用结果取历史值、循环边界不出现 `0 to -1`）。首次粘贴若报错，
   把错误行发我。

## 最后一句

这两个脚本只负责**把形态画准**，不声称它有边际。本仓库 `53`、`57`、`58` 号脚本
已经把四个趋势过滤器、斐波那契回撤位、Impulse MACD 分别拿去对过**去杠杆零假设**
（同敞口 / 同回撤的买入持有），全部没过。形态识别要变成钱，还差一整套证据。
