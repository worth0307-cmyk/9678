# 输入与样式说明书

两个指标：`quasimodo_zones.pine`（QM 供需区）、`impulse_wave_12345.pine`（推动浪 1-2-3-4-5）。

---

## 先说一件会反复踩到的事：输入页 vs 样式页

TradingView 的**「样式」标签页只接受 `plot` 家族的输出** —— `plot` / `plotshape` /
`plotchar` / `fill` / `bgcolor` / `hline`。这几种东西才会出现在样式页里，带着颜色选择器、
不透明度滑块、厚度、线条样式那一整套控件。

**`line` / `box` / `label` / `table` 这类绘图对象永远进不了样式页。** 这是 TradingView
的设计，不是脚本的取舍。而 QM 的区域框、推动浪的浪线，只能是绘图对象——因为它们连接
的是**任意两根 bar**，`plot` 做不到（`plot` 每根 bar 只能给一个值）。

所以两个脚本都是**双层**的：

| | 画什么 | 在哪调 |
|---|---|---|
| 绘图对象层 | 区域框、QM 虚线、浪线、推演斜线、点位标签 | **输入页 · ④ 样式** 组 |
| plot 层 | 最近的那对供需区、推演目标价、事件标记、背景 | **样式页**（你截图里那套 UI） |

两层是**重叠**的。只想要一层：在样式页把 plot 层全部取消勾选，或者反过来，把输入页
④ 组里的标签/骨架开关关掉。

# 一、`quasimodo_zones.pine`

## ① 摆动点

### `Pivot 左侧根数` — 默认 5

`ta.pivothigh(high, left, right)` 里的 `left`。一个 bar 要成为摆动高点，它的最高价必须
**严格高于左边 5 根**的最高价。

- **调大**：结构更少更粗，只认大波段。日线做波段建议 8–15。
- **调小**：结构更碎，噪声多。`left=2` 在 15 分钟图上会遍地是形态。
- 这个数字**不是时间**，是根数。日线 5 = 一周，1h 图 5 = 5 小时。换周期要重调。

### `Pivot 右侧根数` — 默认 5

`right`。同样是根数，但它额外决定了**确认延迟**：枢轴要等右边 5 根走完才能确认，
所以形态最早只能在真实 LL 之后 5 根被报出来。

这不是缺陷，是「不偷看未来」的代价。**想让信号更早来就调小，但结构会变碎；两者不可兼得。**
一般让它等于 `left`。

## ② 区域

### `ATR 周期` — 默认 14

只用来量「一个正常的波动幅度是多大」，给区域厚度定基准。14 是 Wilder 原始值，
没有特别理由要改。

### `区域最小厚度 = ATR ×` — 默认 0.5

区域厚度取 `max(枢轴那根的影线长度, ATR × 这个倍数)`。

**为什么要有下限**：如果 H 那根是根光头阳线（没有上影线），影线长度是 0，区域会退化成
一条零厚度的线，价格永远「碰不进去」。这个倍数就是兜底。

- **0.5** ≈ 半个日波动。BTC 日线上大约 1.5–2%。
- **调大到 1.0–1.5**：区域变厚，更容易被碰到，信号更多但更松。
- **调到 0**：完全依赖影线长度，遇到光头K线就出问题。不建议。

### `区域构造` — 默认「QML 向外扩」

这是**你规格书里唯一一处真正含糊的地方**，两种读法结果不同：

| 选项 | 看跌区 | 区域在 QM Level 的 |
|---|---|---|
| **QML 向外扩**（你写的） | `[QML, QML + 厚度]` | **上方** |
| 枢轴K线影线（常见画法） | `[H那根实体上沿, H那根最高价]` | **下方** |

差别不是美观问题——它决定了「价格进区」发生在**突破 QML 之前还是之后**。
第一种：价格必须先涨到 QML 才算进区。第二种：价格还没到 QML 就已经进区了。

### `保留最近几个形态` — 默认 10

FIFO 上限，超出就删最旧的那个（连同它的框、线、5 个标签 = 7 个对象）。

**为什么要有上限**：TradingView 每个指标最多 500 条线 / 500 个 box / 500 个 label。
撞上限之后 TradingView 会**静默丢弃**最老的对象，看起来就像「有的线不见了」。
10 个形态 = 70 个对象，很安全。调到 60 = 420 个，接近天花板了。

## ③ 显示 / 警报

| 输入 | 默认 | 说明 |
|---|---|---|
| 看跌 · 供给区 | `#ef5350` 红 | 框、虚线、H/L/HH/LL 标签的颜色 |
| 看涨 · 需求区 | `#26a69a` 绿 | 同上，镜像 |
| 已失效 | `#787b86` 灰 | 形态死掉后，**五个标签 + 框 + 虚线一起变灰** |
| 区域填充透明度 | 88 | 0 = 实心，100 = 全透明。88 大约是一层薄色 |
| 标注 H/L/HH/LL | 开 | 关掉能省 4 个对象/形态，密集时有用 |
| 标注 QM | 开 | 触发之后这个标签会变成 `QM ✓` |
| 隐藏已失效形态 | 关 | 打开 = 死掉就**删除**（不是变灰）。想只看活跃区就打开 |

## 四个状态怎么读

```
形成  ──► 回踩进区 ──► 触发
  │                      （框边框加粗 + 标签打勾 QM ✓）
  └──► 失效（全部变灰，框停止向右延伸）
```

- **形成**：H→L→HH→LL 确认。注意是在真实 LL 之后 `right` 根。
- **回踩进区**：看跌时 `high ≥ 区域下沿`。只触发一次。
- **触发**：进过区之后，出现一根**收盘回到区外**的K线。默认模式下区域下沿就是
  QM Level，所以等价于「收盘价低于 QM Level」。**进区和触发允许在同一根**——
  上影线插进去、收盘掉回来，那正是经典的拒绝形态。
- **失效**：收盘价穿出区域**外沿**（看跌 = 上沿）。

# 二、`impulse_wave_12345.pine`

## ① ZigZag（ATR 反转阈值）

### `ATR 周期` — 默认 14

这里的 ATR 不是装饰，它**定义了整个枢轴序列**。阈值 = `ATR(14) × 倍数`。

### `级别「细 / 中 / 粗」阈值 = ATR ×` — 默认 2 / 4 / 8

（级别原来叫 A / B / C。场景推演会画调整浪 A、B、C，「B 级别的 A 浪」没法读，所以改名。）

**这是全脚本最重要的三个数字。** 一条腿必须让收盘价从极值反向走出
`ATR × 倍数` 才算结束，否则一直延伸。

为什么用 ATR 而不是 pivot 的根数：`left=5` 在暴涨和横盘里量到的东西完全不是一回事；
你要的三个级别是**幅度**，不是根数。用根数做级别，三条 ZigZag 在高波动段会塌成同一条。

实测（本仓库 SOL 日线 1713 根）：

| 级别 | 阈值 | 确认的枢轴数 | 有效数浪 |
|---|---|---|---|
| 细 | ATR×2 | 120 | 0 |
| 中 | ATR×4 | 46 | 3 |
| 粗 | ATR×8 | 12 | 0 |

**「细」是 0 不是 bug**：它那两组命中的浪里都有两个枢轴落在同一根K线上（零长度线段），
被 `rBi` 规则筛掉了。**「粗」是 0 也不是 bug**：它唯一一组跨 752 根，被跨度上限筛掉了。

调参时先打开 ④ 组的 `画出 ZigZag 骨架`，肉眼看三条折线是不是三个层次。
**塌成同一条就把倍数拉开**，比如 ×1.5 / ×4 / ×10。

### `阈值按周期自动缩放` — 默认 **开**

**打开时下面三个手动值不生效**，脚本按图表周期自己选：

| 图表周期 | 细 / 中 / 粗 |
|---|---|
| 月线 | 0.25 / 0.5 / 0.75 |
| 周线 | 0.5 / 1.0 / 1.5 |
| 日线 · 4小时 | 2 / 4 / 8 |
| 4小时以下 | 3 / 6 / 12 |

状态表第二列显示的是**实际生效**的倍数，表头会写 `阈值(自动)` 还是 `阈值(手动)`。
想手动调就把这个开关关掉。下面这一节讲的是为什么需要它。

### ⚠ 为什么阈值不能跨周期通用

阈值是 ATR 倍数，**幅度上跨周期自适应，但枢轴数量不会** —— 枢轴数取决于图上有
多少根K线。同样的倍数，日线有 1700 根可用，周线只有 250 根。

实测（本仓库数据重采样，截至 2026-09-09）：

| ETH | 总根数 | ATR×2 | ATR×4 | ATR×8 |
|---|---|---|---|---|
| **日线** | 1713 | **114** 枢轴 | 42 | 15 |
| **周线** | 246 | **14** 枢轴 | 7 | **3** |

**3 个枢轴连一个 6 点窗口都凑不出来**，所以周线上「粗」永远是空的。
这不是 bug，是默认值只按日线校准。

周线上把三个倍数缩到**日线的 1/4 左右**，枢轴密度就回来了：

| ETH 周线 | ATR×0.5 | ATR×1.0 | ATR×1.5 | ATR×2.0 |
|---|---|---|---|---|
| 枢轴数 | 112 | 48 | 28 | 14 |
| 命中 | 1 | 1 | 0 | 0 |

**推荐起点**

| 周期 | 细 / 中 / 粗 |
|---|---|
| 1周 | 0.5 / 1.0 / 1.5 |
| 1天 | 2 / 4 / 8（默认） |
| 4小时 | 2 / 4 / 8 |
| 1小时及以下 | 3 / 6 / 12 |

上面那个自动开关就是干这件事的。手动模式下，状态表的 `枢轴·命中` 列是给这件事看的：
**枢轴数低于 12 会直接报「⚠ 枢轴仅 N 个，阈值偏大 · 试试调到 1/4」**。

### `启用级别「细 / 中 / 粗」` — 默认 开 / 开 / **关**

「粗」默认关。它和「中」经常选中同一个场景（脚本会自动去重，只画更细的那个）。

## ② 校验规则

三条硬规则写死在代码里，不可调（那是艾略特的定义，调了就不是推动浪了）：

```
浪2 不跌破浪起点 P0
浪3 不是 1、3、5 中最短的
浪4 不进入浪1 的价格区间
```

顺带一提：这三条**已经蕴含「P3 越过 P1」**（因为 P4 越过 P1 且 P3 越过 P4），
所以不需要单列第四条。

### `浪4 允许重叠浪1 的比例` — 默认 0（严格）

「浪4 不进浪1 价格区间」是艾略特最硬的一条。但**对角线形态（leading / ending
diagonal）在艾略特里本来就允许重叠**，所以给一个容差，单位是浪1 长度的比例。

实测 BTC 日线（2026-09-09 收盘）三个级别的浪4 侵入量：

| 级别 | 浪1 长度 | 浪4 侵入 | 占浪1 |
|---|---|---|---|
| A | 23,749 | 7,844 | **33.0%** |
| B | 45,608 | 2,229 | **4.9%** |
| C | 35,543 | 8,372 | **23.6%** |

设到 `0.06`，级别 B 那一组 1-5 成立并画出推演；A 和 C 仍然出局。

**调这个值是在放宽定义，不是在改进检测。** 放得越宽，命中越多，含义越少。

### `浪5 必须超越浪3 端点` — 默认 开

这是三条之外我加的。关掉 = 允许**衰竭浪**（truncated fifth）。
衰竭浪在艾略特里合法但少见；默认打开能少掉很多噪声数浪。

### `浪3 ≥ N×浪1 时加粗标 ★` / `加分比例 N` — 默认 开 / 1.618

**纯装饰，不影响是否命中。** 斐波那契比例是加分项不是硬条件——把 1.618 当门槛
会筛掉大量真实的推动浪。达标时浪3 那一段线加粗、标签加 ★。

### `每个级别保留最近几组` — 默认 1

三个级别 × 2 组 = 30 条浪线 + 3 条推演线抢同一片像素。默认 1 组，想看历史再往上加。

### `一组浪最大跨度（根，0 = 不限）` — 默认 300

**这条是为了让线跟着价格走。**

一组浪的连线是两个枢轴之间的**直线段**。枢轴隔了几百根的时候，两端都在屏幕外，
中间那条直线就横穿图表，落在和当地K线毫无关系的价位上——看起来就像「线没跟着价格变化」。

实测：SOL 日线 ATR×8 唯一一组浪跨 **752 根**（2022-12 的 7.78 到 2025-01 的 295.60）。
默认 300 把它筛掉。

**副作用**：日线上级别 C 经常是 0 组。那不是坏了，是日线上 ATR×8 的浪本来就以年计。
想看就把这个数调到 0（不限）或 800。

## ③ 场景推演

**判断「现在」处在艾略特周期 1-2-3-4-5-A-B-C 的哪一浪，从现在往后画几段。**

### 为什么重写

旧版只认得「正在走浪5」这一个位置，外加「刚确认一组 1-5 之后的一小段时间」。
另外七个位置 —— 正在走浪1、2、3、4、A、B、C —— 什么都不画。把历史上每一根都当成
「最后一根」抽样实测，旧版画得出推演的比例：

| | 周线 | 日线 | 4小时 |
|---|---|---|---|
| BTC 细 / 中 / 粗 | 17% / 8% / 5% | 8% / 28% / 0% | 25% / 8% / 0% |
| ETH 细 / 中 / 粗 | 10% / 13% / 0% | 7% / 25% / 0% | 10% / 7% / 0% |
| SOL 细 / 中 / 粗 | 0% / 0% / 25% | 2% / 20% / 0% | 18% / 13% / 0% |

新版：同样 1620 个抽样点，**99.2% 画得出**，剩下 0.8% 全部是「图上枢轴还不到 2 个」。
路径自检（时间递增、每段方向正确、浪2 不破起点、浪4 不进浪1、B 不越过浪5、
C 不破推动浪起点）**0 处违规**。

### 怎么判断「现在在哪一浪」

对 8 个位置逐一检验：最近 k+1 个枢轴能不能当作 P0..Pk（k = 当前在走第几段），
方向交替、时间递增、走完的部分全部符合硬规则，**正在走的那段已经走出来的部分也不违规**
（比如正在走浪2，就不能已经跌破浪1 起点）。

**取能解释最多枢轴的那一个。** 全都不成立时，退回到「新的一浪1 正在走」—— 这个
解读永远成立，所以只要有 2 个以上枢轴就一定画得出来。

### 高度：斐波那契，再用硬规则夹紧

| 这一段 | 终点 | 输入项 |
|---|---|---|
| 浪2 | 回撤浪1 的 0.618 | `高度 · 浪2 回撤浪1` |
| 浪3 | 浪2 终点 + 1.618 × 浪1 | `高度 · 浪3 = 浪1 ×` |
| 浪4 | 回撤浪3 的 0.382，且不进浪1 | `高度 · 浪4 回撤浪3` |
| 浪5 | 浪4 终点 + 1.0 × 浪1，且越过浪3 | `高度 · 浪5 = 浪1 ×` |
| A / B / C | ABC 合计回撤推动浪 0.5；B 回撤 A 0.618；C = A | `ABC 合计回撤` / `B 回撤 A` |

两条自动切换的指引：

- **浪3 延长时，「浪5 = 浪1」可能连浪3 的高点都过不去**，推出一个和浪3 平头的浪5。
  这时改用另一条常用指引：浪5 = 0.618 × (浪1 起点 → 浪3 终点)。
- **A/B/C 的分配**：净回撤 = A − B + C = (2 − 0.618) × A，所以 A = 合计回撤 ÷ 1.382。
  这样 C 的终点正好落在「合计回撤」那个价位上。

### 角度：每段的耗时 = 价格长度 ÷ 同类腿的实测速度

推动腿（1 / 3 / 5 / A / C）和调整腿（2 / 4 / B）**分开算速度**：

- 本组里已经走完的腿，各算一票
- 正在走的那段，走了 3 根以上也算一票
- **本级别最近 10 条腿的速度中位数，也算一票**

最后一票是防止被单条腿带偏：只有一条腿可参考时（比如刚开始一个新的浪1），它可能
恰好走得特别慢或特别快。实测 ETH 日线「中」级别，不加这一票时推出来的浪3 要走 133 根
（因为参考的浪1 很慢），加了之后是 65 根。

结果：**推出来的浪3 和实测的浪1 一样陡，浪4 和实测的浪2 一样缓。**

### 正在走的那一段，有三种情况

| 情况 | 怎么画 | 状态表显示 |
|---|---|---|
| 还没到目标 | 从「现在」画到目标 | `(3) 进行中` |
| 越过目标、**还在走**（极值就在最近两根） | 取下一档延长目标：浪3 1.618→2.618、浪5 1.0→1.618、浪2 0.618→0.786 …… | `(3) 延长中` |
| 越过目标、**已回头** | 暂按「这一段在极值处走完」，从极值处接下一段，标签带 `?` | `(3)? 越过目标·已回头` |

第二种是专门修的：旧版在「越过目标、还在走」时会直接宣布这一浪结束、立刻画反转 ——
价格明明还在创新高，推演却说现在就掉头。

### 其它细节

- **两个级别选中了同一个起点、同一个位置时，推出来的路径完全一样，只画更细的那个**，
  另一个在状态表里写「同「中」的场景，不重复画」。实测 BTC 日线的「中」和「粗」就是这样。
- **推演只在最后一根上画，每根都重算。**
- 浪2 回撤超过 88.6% 的计数合法但很脆弱（离作废只差一点），状态表会标
  `⚠浪2回撤98%` 这样的提示。
- 未来最多只能画到 500 根之后。超出时整条路径**等比例压缩**，各段角度的相对关系不变。

### 悬停看每个点的依据

图上的推演标签默认只写浪名，不挡K线。**鼠标移到任何一个标签上**，弹出正常字号的详情。
下面是 BTC 日线（截至 2026-09-09）「细」级别 `A` 那个点的实际内容：

```
级别「细」 · 推演第 3 段 · A
终点 74,370.5   离现价 -5.0%
约 36 根后 ≈ 2026-10-15（按连续交易估算）

高度：ABC 合计回撤推动浪的 0.5；按锯齿形分配 A = 合计 ÷ (2 − 0.618)

角度：这一段 -9,417.2 / 15 根 = -627.8 / 根
（推动腿实测速度 623.5 / 根）
```

- **高度**写的是**实际起作用**的那条规则。硬规则夹紧只有真触发了才会写出来，比如
  「会进浪1 区间，被抬到浪1 终点之外」「浪3 比浪1 短，浪5 不能比浪3 长」。
- **角度**给出这一段画出来的斜率，和它参照的同类腿实测速度。两者不完全相等是正常的：
  第一段是从现价量起的，超过 480 根的路径还会等比例压缩。
- **日期**按「每根K线连续」估算。加密货币 7×24 交易，基本准确；股票遇到周末和节假日会偏早。
- 带 `?` 的点（越过目标、已回头）悬停会写明原目标是多少、实际走到了哪。
- 已确认的 `(1)`..`(5)` 也能悬停：这一浪涨跌多少、走了几根、和浪1 的比例。

Pine 指标没法响应鼠标点击，所以做不成「点一下放大」，悬停浮窗是最接近的原生功能。

### 手机上怎么看

手机没有「悬停」，浮窗用不了。在 ④ 组把 **`详情显示方式`** 改成 **「直接显示（手机）」**：

1. 推演标签写全：`细 A  74,370.5  -5.0%`
2. 状态表下方多出一块明细，列出 `直接显示时列出哪个级别` 选中的那一级的每一个推演点：

### `往后推几段` — 默认 4

比如正在走浪3：画 (3) → (4) → (5) → A。正在走 A：画 A → B → C → 下一轮的 (1)′。

### `在推演终点价画水平射线` — 默认 开

从**推演终点**往右延伸。

旧版从当前K线画起，结果是：终点价离现价远的时候（比如「中」级别推演到 +52%），这条线落在
当前视图里，TradingView 自动缩放把它算进去，**纵轴被撑开、K线被压扁**。实测默认视图
（最近 150 根 + 右侧 40 根）的纵轴被撑大的倍数：

| | 旧版 | 新版 |
|---|---|---|
| BTC 日线 | ×1.33 | ×1.04 |
| BTC 4小时 | ×1.07 | ×1.00 |
| ETH 日线 | ×2.38 | ×1.30 |
| SOL 日线 | ×2.38 | ×1.64 |

剩下的撑大来自**推演路径本身**：比如一个 +30% 的浪3 目标，它的第一段就在视图里往上走。
那是推演的内容，不是画错。如果想让K线永远占满纵轴，用 TradingView 自带的设置：
**右键点价格轴 → 勾选「仅缩放价格图表」**（Scale price chart only）。之后自动缩放只看K线，
推演线超出的部分在图边被截掉，不会再压扁K线。

|---|---|---|

# 六、必须知道的四条

1. **重绘。** QM 不重绘（`ta.pivot*` 是局部的，只看左右各 N 根）。推动浪的
   **场景推演每根重算，最新一浪会重绘**，而且 ZigZag 路径依赖——往左拖加载更多历史后整串枢轴可能挪位。
   这不是实现缺陷，是 ATR-ZigZag 没有「局部」定义：第 k 个枢轴取决于第 1 个。

2. **确认延迟。** QM 的形态在真实 LL 之后 `right` 根才报出来。区域框画在 LL 那根，
   但**监控是从确认那根开始的**——框覆盖的前 `right` 根从未被判定过。

3. **对象上限。** 每指标 500 线 / 500 box / 500 label。撞上限 TradingView 会**静默丢弃**
   最老的对象，看起来就像「有的线不见了」。保留数调大之前先算一下。

4. **没有在 TradingView 上编译运行过。** 我没有 Pine 编译器。两份代码做过静态审查
   （括号配平、声明顺序、函数先定义后调用、`plot` 家族在全局作用域、
   无 `int/int` 整数除法、循环边界不出现 `0 to -1`、**续行缩进不是 4 的倍数**），
   核心算法另外用 Python 逐行移植，在真实 BTC/ETH/SOL 数据上对过。报错把行号发我。
